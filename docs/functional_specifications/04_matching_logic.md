# マッチングロジック・スコア計算 仕様書

## 1. マッチングスコア計算
ユーザー同士の属性の親和性を数値化（0〜100）するロジック。

### 1-1. 配点重み付け
合計 100 点満点で以下の重み付けを行う。
*   **タグ (`tags`)**: 40% (40点)
*   **マッチング目的 (`looking_for`)**: 25% (25点)
*   **ジャンル (`genres`)**: 20% (20点)
*   **楽器 (`instruments`)**: 15% (15点)

### 1-2. 計算式
各カテゴリについて、自分と相手の配列の「重なり（一致数）」を比較。
```
Score = (共通タグ数 / 最大タグ数) * 40
      + (共通目的数 / 最大目的数) * 25
      + (共通ジャンル数 / 最大ジャンル数) * 20
      + (共通楽器数 / 最大楽器数) * 15
```
※最大数は、自分と相手のうち数が多い方の要素数（最低1）。

## 2. 優先度ソート (Discovery Engine)
取得したユーザーリストを並び替える最終的なアルゴリズム。

1.  **Pro優先 (is_pro)**:
    `b.is_pro` が `true` のユーザーをスタックの上位へ。
2.  **マッチスコア (matchScore)**:
    スコアの高い順（降順）。
3.  **距離 (distance)**:
    拠点が近い順（昇順）。データが欠損している場合は最後尾（9999km扱い）。

## 3. レート制限 (安全策)
スワイプやメッセージ送信、プロフィールの更新には API レート制限を課し、スパム行為を防止する。
*   `withRateLimit` ラッパーによる制御。

## 4. アルゴリズムの特長
*   **相対評価の採用**: 分母に「最大要素数」を採用することで、例えば「何でもいいから100個のジャンルを登録しているユーザー」が不当に高い関心度を得るのを防ぎ、真に好みが一致しているユーザー同士を繋げる。
*   **高速性能**: 重い距離計算や複雑なスコア算出を最終的な上位数十名（limit 50）に対してのみ実行することで、フロントエンドのレスポンス性能を維持している。
