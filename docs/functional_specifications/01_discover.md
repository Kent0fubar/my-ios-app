# 探す (Discover) 機能仕様書

## 1. 機能概要
他のユーザーをカード形式で閲覧し、直感的なスワイプ操作でマッチングの意思表示を行う。

## 2. ユーザーインターフェース (UI)
*   **カードスタック**: 重なり合った3枚のカードを表示。
*   **スワイプ操作**:
    *   右スワイプ: Like (興味あり)
    *   左スワイプ: Nope (興味なし)
    *   上スワイプ: Super Like (強い興味)
*   **アクションボタン**: 画面下部に配置されたボタンでも操作可能。
*   **ローディング表示**:
    *   データ取得中は ActivityIndicator を表示。
    *   「ミュージシャンを探しています...」というメッセージを表示。

## 3. ビジネスロジック
*   **表示対象の抽出条件**:
    *   自身がまだスワイプしていないユーザー。
    *   自身がブロックしていない、かつ相手からもブロックされていないユーザー。
    *   適用中のフィルター条件（距離、楽器、ジャンル等）に合致するユーザー。
*   **ソート順（優先度）**:
    1. **プロフィールブースト (Pro版限定)**: `is_pro` フラグを持つユーザーを最優先。
    2. **マッチングスコア**: 互換性スコアの高精度ソート。
    3. **距離**: 活動拠点が近い順。
*   **スワイプ制限 (無料会員)**:
    *   1日 30 回まで。
    *   制限時は課金誘導モーダルを表示。
*   **マッチング成立**:
    *   相互 Like 時に `matches` テーブルにレコードを作成。
    *   フルスクリーンでマッチ通知を表示し、即座にメッセージ送信を可能にする。

## 4. 詳細な実装仕様

### 4-1. スマート取得エンジン
データ取得（`getDiscoverUsers`）の際、以下のステップでバックエンド通信が発生する。
1. **除外リストの生成**: 自身のスワイプ履歴（`swipes`テーブル）とブロック履歴（`blocks`テーブル）から、非表示対象のUUIDリストを生成。
2. **Supabaseフィルタリング**: データベースレベルで、除外リストに含まれず、かつ各種フィルター条件（楽器・ジャンルの重なりなど）に合致するユーザーを最大50名抽出。
3. **Pro優先ソート**: 取得後のリストに対し、フロントエンド側で `is_pro` フラグによる最終ソートを実行。

### 4-2. カードスタックのUX制御
ユーザーにストレスのない体験を提供するため、以下の状態管理を行う。
*   **非同期状態 (`isLoading`)**: 通信中はActivityIndicatorを表示。古い情報の残像や、データの未取得を「全員チェック済み」と誤認するのを防ぐ。
*   **バッファリング**: 常に3枚のカードを先行してレンダリングし、スワイプ時の滑らかなアニメーションを保証する。
